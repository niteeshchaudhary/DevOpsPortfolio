---

# Scene Overview

The glowing river created by the `git push` reaches a gigantic hydroelectric dam carved into the mountain.

This isn't an ordinary dam.

It is an enormous industrial version control facility.

Every drop of glowing water represents a line of code.

Nothing passes through until it has been validated, recorded, and assigned a version.

The entire mountain has transformed from nature into engineered infrastructure.

# Merge Conflict (Interactive Event)

At approximately 45% scroll,

a second branch attempts to merge.

The gates refuse to open.

Amber warning lights activate.

Pressure increases.

Red indicators blink.

A robotic inspector arrives.

The visitor hovers over the merge chamber.

Tooltip appears:

> **Merge Conflict Detected**
>
> Incoming changes overlap with Main.

A repair robot examines both pipelines.

The conflicting section glows red.

The robot adjusts two control valves.

The lights turn green.

The gates open.

The streams merge smoothly.

Visitors understand conflict resolution without seeing code.

# Learning Objective

By the end of Scene 02, visitors should intuitively understand:

* Source code is carefully versioned before automation begins.
* Branches allow parallel development.
* Commits create a permanent history.
* Merge conflicts are resolved before production.
* Protected branches safeguard stability.
* A successful merge automatically triggers the CI/CD pipeline.

Without reading documentation, visitors should feel that Git is not merely a repository—it is the intelligent water control system that governs the entire software delivery ecosystem.
